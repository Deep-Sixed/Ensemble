# Karpathy Guidelines Skill

Use this for non-trivial coding, reviewing, fixing, and refactoring tasks.

- Surface assumptions before coding when requirements are ambiguous.
- Prefer the smallest implementation that solves the requested behavior.
- Avoid speculative abstractions, extra configuration, and unrelated cleanup.
- Keep diffs surgical: every changed line should trace to the task.
- Match existing project style even when another style is tempting.
- Remove only dead code introduced by the current change unless asked.
- Define verifiable success criteria before larger edits.
- Verify with focused tests, type checks, compile checks, or live smoke commands.
- If the task is unclear or success cannot be verified, say what is missing.

For trivial one-line changes, use judgment and keep the workflow lightweight.
